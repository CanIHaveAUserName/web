01

Mission

I develop games and applications as independent personal projects, spanning game development, tooling, and server infrastructure. The goal is software that's reliable across the platforms people actually run — not just the one I happen to build on.

All of my current development and testing hardware is x86_64. I don't own any ARM64 devices, which means every build I ship today is untested on an entire, increasingly common class of hardware.

02

Why ARM64 matters

ARM64 isn't a niche target anymore — it covers Apple Silicon, a growing share of Windows and Linux laptops, cloud instances, Linux SBCs, and handheld gaming devices. Shipping without testing on it means these problems get found by users instead of by me:

  • Missing dependency builds — libraries or engine plugins that only ship x86_64 binaries
  • Bad low-level assumptions — endianness, pointer size, or x86 SIMD code with no ARM (NEON) equivalent
  • ARM-only runtime bugs — crashes or rendering issues that never appear on x86_64
  • Architecture-specific performance issues — a build that's fine on x86_64 but unacceptably slow on ARM
