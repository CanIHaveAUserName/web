Build Your Own Minecraft
IP-Hiding Relay.

A self-hosted TCP relay that lets anyone connect to your Minecraft Java server normally, while the public connection terminates at an Azure VM instead of your home network. Players install nothing. It is not free, but a small relay VM can be a much cheaper, better-value option than a managed Minecraft host while avoiding a home-router port forward.

1. How it works

The Azure VM is the only publicly reachable Minecraft endpoint. HAProxy accepts the player's TCP connection and forwards it over Tailscale to the Minecraft server's private Tailscale address.

Important: Tailscale is only used between the server owner's machines. Players do not need Tailscale, a VPN, a mod, or a custom launcher.
Player IP and bans: This raw TCP relay hides players' real IP addresses from the Minecraft Java server console: the server sees the relay's Tailscale address instead. As a result, vanilla IP bans are much less useful—banning that address can block every player using the relay. Use Minecraft accounts, permissions, logs, and server-side moderation tools rather than relying on IP bans alone.

2. Azure relay pros and cons

This relay is a good fit when you want a stable, paid cloud endpoint while keeping the Minecraft server at home.

Pros

  • Hides your home IP and removes the need to expose TCP 25565 on your home router.
  • Players join normally with a public IP or domain; they do not need Tailscale, mods, or a custom launcher.
  • Azure offers multiple regions and VM sizes, so you can choose a location near your players and scale the relay if needed.
  • A static public IP and Azure networking controls make the endpoint practical for a long-running server.
  • The VM only relays traffic, so even a small instance is usually enough.

Cons

  • It has an ongoing Azure cost, plus possible public-IP and bandwidth charges.
  • Initial setup involves Azure billing, networking rules, SSH, Tailscale, and HAProxy.
  • Players' real IPs are hidden from the Minecraft server, which makes vanilla IP bans ineffective for individual players.
  • Latency includes an extra trip through Azure, so choose a region that is sensible for both the host and players.
  • The relay is another service to maintain: updates, logs, firewall rules, and VM availability still matter.

3. Create the Azure VM

Create a Linux VM in the Azure Portal.

Cost and value: This setup still has a monthly Azure cost (and possibly public-IP or bandwidth charges). For a small server, though, the relay needs very little compute, so it can be substantially cheaper than paying for full managed cloud hosting. You keep control of the Minecraft server at home while putting the public-facing connection on the VM—often a dramatically better value for the money.
SettingRecommended value
Operating systemUbuntu 24.04 LTS
ArchitectureARM64 is fine
CPU1–2 vCPU
RAM1–2 GB is generally plenty for the relay
Public IPYes
Inbound portsSSH (22) and Minecraft (25565)

The relay does not run Minecraft, so it does not need the amount of RAM normally allocated to a Minecraft server.

Connect over SSH

ssh azureuser@YOUR_AZURE_PUBLIC_IP
Do not expose your home Minecraft port. The Azure VM will be the public endpoint. Your home router should not forward TCP 25565 once the relay is working.

4. Install Tailscale on the Azure VM

curl -fsSL https://tailscale.com/install.sh | sh
sudo tailscale up

Authenticate the VM into the same Tailscale network as the computer running Minecraft.

Check the network:

tailscale status

Find the Tailscale IPv4 address of the Minecraft PC. On Windows:

tailscale ip -4

It will normally look like 100.x.x.x.

Test the private connection

sudo apt update
sudo apt install netcat-openbsd -y

nc -vz MINECRAFT_PC_TAILSCALE_IP 25565

You want:

Connection to 100.x.x.x 25565 port [tcp/*] succeeded!
If this test fails, fix Tailscale, Windows Firewall, or Minecraft first. Do not move on to HAProxy until Azure can reach the Minecraft PC over Tailscale.

5. Configure Minecraft

Open your Minecraft server's server.properties.

server-ip=
server-port=25565

Leave server-ip blank. Restart the Minecraft server after changing it.

Make sure Windows Firewall permits TCP 25565 from the Tailscale network/interface.

6. Install and configure HAProxy

sudo apt update
sudo apt install haproxy -y

sudo cp /etc/haproxy/haproxy.cfg /etc/haproxy/haproxy.cfg.backup

Edit the configuration:

sudo nano /etc/haproxy/haproxy.cfg

Replace the configuration with:

global
    log /dev/log local0
    log /dev/log local1 notice
    daemon

defaults
    log global
    mode tcp
    option tcplog

    timeout connect 10s
    timeout client 1h
    timeout server 1h

frontend minecraft
    bind *:25565
    default_backend minecraft_home

backend minecraft_home
    mode tcp
    server home MINECRAFT_PC_TAILSCALE_IP:25565 check

Replace MINECRAFT_PC_TAILSCALE_IP with the actual Tailscale address of the Minecraft PC.

Validate the configuration

sudo haproxy -c -f /etc/haproxy/haproxy.cfg

You want:

Configuration file is valid

Start HAProxy

sudo systemctl restart haproxy
sudo systemctl enable haproxy
sudo systemctl status haproxy

Verify that it is listening:

sudo ss -lntp | grep 25565

You should see something similar to:

LISTEN 0 4096 0.0.0.0:25565

7. Configure Azure networking and firewall

Azure Network Security Group

In Azure Portal, open the VM's networking settings and allow:

ProtocolPortDirectionAction
TCP22InboundAllow
TCP25565InboundAllow

For better security, restrict SSH port 22 to your own source IP when practical.

UFW

If UFW is enabled:

sudo ufw status

Allow the required ports:

sudo ufw allow 22/tcp
sudo ufw allow 25565/tcp
Only TCP 25565 needs to be publicly available for this Minecraft Java relay. Do not publicly expose the Tailscale interface.

8. Test the public relay

Find the Azure public IPv4 address:

curl -4 ifconfig.me

From a Minecraft client, connect to:

YOUR_AZURE_PUBLIC_IP:25565

9. Add a Minecraft domain

If your domain is managed through a DNS provider such as Cloudflare, create an A record:

TypeNameValue
AmcYOUR_AZURE_PUBLIC_IP

For a normal DNS record, use DNS only rather than an HTTP reverse-proxy mode. HAProxy is handling the Minecraft TCP connection.

Players can then connect with:

mc.example.com

10. Remove the home port forward

After the Azure relay is confirmed working, remove your old home-router rule:

Internet → TCP 25565 → Minecraft PC

Your home network should instead look like:

Internet
   │
   X── Home router :25565
   │
   ▼
Azure VM :25565
   │
   ▼
Tailscale
   │
   ▼
Home Minecraft PC :25565

This keeps the public Minecraft endpoint on Azure rather than your residential connection. It also avoids exposing a port directly from your home router to the Minecraft PC, reducing the risk that comes with port forwarding while still letting players join normally.

Recommended hardening

  • Use a static Azure public IP if the address needs to remain stable.
  • Keep only the required Azure inbound ports open.
  • Restrict SSH access where practical.
  • Use Tailscale ACLs to limit what the relay can reach.
  • Keep Ubuntu, Tailscale, and HAProxy updated.
  • Monitor HAProxy logs for unexpected or abusive traffic.

11. Troubleshooting

HAProxy says the backend is DOWN

nc -vz MINECRAFT_PC_TAILSCALE_IP 25565

If this fails, troubleshoot Tailscale, Windows Firewall, or Minecraft rather than HAProxy.

Azure receives no public connections

sudo tcpdump -ni any tcp port 25565

If no packets arrive while a player tries to connect, check the Azure NSG and local firewall.

HAProxy is listening but Minecraft cannot connect

sudo journalctl -u haproxy -f
sudo ss -lntp | grep 25565
tailscale status
tailscale ping MINECRAFT_PC

A Tailscale result showing direct is generally preferable to a DERP relay for latency.

HAProxy repeatedly reports DOWN/UP

This indicates its backend health check is intermittently failing. Check Tailscale connectivity, the Windows firewall, Minecraft server availability, and network stability.
